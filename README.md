# 隱形浮水印實驗室

上傳一張圖當**金鑰**，另一張是你要蓋章的**作品**。蓋完肉眼看不出差別，然後你自己把它驗出來、自己把它弄壞。

整套演算法沒有黑箱，每一步的中間產物都畫給你看。**所有運算都在瀏覽器裡，圖片不會離開你的電腦。**

→ **[打開實驗室](https://yazelin.github.io/invisible-watermark-lab/)**

## 先搞清楚你要哪一種浮水印

浮水印有兩種完全不同的題目，取捨也完全不同。看完你可能會發現該用別的工具，那也是這個 repo 的目的。

| 題目 | 需求 | 代表 |
|---|---|---|
| **洩漏溯源** | 圖裡要載得動 ID，才知道是誰外流的 | [invisible-watermark](https://github.com/ShieldMnt/invisible-watermark)（dwtDct）、RivaGAN |
| **歸屬證明** | 只要回答「這是不是我的」，一個位元就夠 | **本專案** |

因為只需要一個位元，我們可以把全部的工程餘裕拿去換抗破壞性：平鋪、暴力搜尋、只看整體相關性。溯源型要精準到每個位元的位置，所以對裁切、縮放特別脆弱。

**第三種情況也要講**：要防專業的、有心的移除，兩種都不夠，那是另一個等級的問題。開源工具防的是順手盜用，不是防偽。

## 演算法

1. **金鑰圖 → 指紋**：轉灰階、切成 N×N 塊取平均、減平均使總和為零、正規化到 −1 到 +1
2. **指紋 → 平滑場**：每 16 像素一個節點，格內位置過 smoothstep 再雙線性內插
3. **蓋章**：`藍 = 藍 + 2 × 場值`，近白近黑振幅減半，加 4×4 有序抖動再取整
4. **驗證**：每 16×16 格算 `藍 −(紅+綠)/2` 平均 → 減四鄰做高通 → 3σ 截尾 → 與指紋逐格相乘相加 → 標準化成 t → 取所有候選的最大值當 z

每一步為什麼是這樣，頁面上都有解釋，包含四次做壞的版本淘汰過程。

## 門檻是量出來的，不是拍腦袋

拿 60 組不相干的金鑰去驗（`node test/calibrate.mjs`）：

| 節點 | 正向 | 乾淨圖 | 蓋了 A、拿別人金鑰驗 | 門檻 |
|---|---|---|---|---|
| 8×8 | 31.6 | ≤ 1.3 | 中位 12.2 / **最高 18.1** | 28 |
| 16×16 | 31.6 | ≤ 1.5 | 中位 8.0 / **最高 10.2** | 16 |

**真正的假陽性來源不是乾淨圖**（那個接近 0），是「別人的金鑰撞到你的場」——搜尋會在數萬個候選裡挑出最像的那個位移，兩個隨機零均值場總有一個對得比較準。

這也是為什麼 **8×8 不只是「logo 認不出來」，而是明顯比較好偽造**。預設 16×16。

## 誠實的界限

- **開源，所以拔得掉。** 防的是順手盜用，不是防偽。
- **金鑰是圖，不是密碼。** 你的 logo 如果是公開的，別人也能算出同一把金鑰、蓋到別的作品上宣稱是你做的。要擋這個得換成帶密鑰的雜湊，而且每件作品用不同的鹽。
- **同一把金鑰蓋很多張圖會被反推。** 指紋固定、內容不相干，蒐集幾張取平均，內容互相抵消、指紋浮出來（平均攻擊）。
- **旋轉會殺死它。** 沒有搜尋角度，這是明確的已知限制。
- **剩下的區域太小就驗不出來。** 極限由剩餘格數決定，不是破壞程度。大約留 200×200 像素以上才穩。
- **未檢出不等於沒被盜。** 只代表這張圖不是、或已無法辨識為用這把金鑰蓋的。

## 站在誰的肩膀上

技術不新。這是 **spread spectrum watermarking**（擴頻浮水印），奠基論文是 Cox、Kilian、Leighton、Shamoon 1997 年發表於 IEEE Transactions on Image Processing 的 *Secure Spread Spectrum Watermarking for Multimedia*。核心想法一樣：把振幅很低的偽隨機圖樣鋪滿整張圖，偵測時用相關性比對。他們埋在 DCT 係數，我們埋在空間域的藍色通道。

其他每一塊也都是既有技術：相關偵測與 t 統計量是訊號偵測理論的教科書內容；利用人眼對藍色空間解析度低是感知模型浮水印的常見手法；平鋪加暴力搜尋做同步是對抗裁切的標準做法；有序抖動是印刷業的老技術。

| 專案 | 做法 | 跟這裡的差別 |
|---|---|---|
| [invisible-watermark](https://github.com/ShieldMnt/invisible-watermark) | Python，dwtDct／dwtDctSvd／RivaGAN | 載得動 ID，可溯源；抗裁切與縮放較弱 |
| [hiddenmark](https://github.com/hvuhsg/hiddenmark) | 瀏覽器端，傅立葉頻域環狀調變 | 方向最接近，頻域天生較抗縮放旋轉，實作複雜 |
| [watermark-js-plus](https://github.com/zhensherlock/watermark-js-plus) | 瀏覽器端，可見＋盲浮水印 | 功能最全，目標是保護網頁與文件 |

這裡自己的只有工程取捨與實測：±2 的振幅、16 像素節點、近白減半、抖動、四次做壞的淘汰過程，以及那張存活表。承認站在別人肩膀上，反而讓實測數據更可信。

## 檔案

```
index.html      工具 + 教學，一頁到底
pure.js         純邏輯：指紋、嵌入、偵測（node 可直接測，頁面用同一份）
field.js        瀏覽器端：金鑰圖 → 指紋 → 平滑場 → 蓋章，附視覺化中間產物
detect.js       尺度搜尋與存活測試的摧殘手法
app.js          頁面互動
test/
  pure.test.mjs   純邏輯 + 三條負控制
  calibrate.mjs   量 null 分布、定門檻
  e2e.mjs         真瀏覽器端到端：蓋章 → 驗證 → 偽造 → 存活矩陣
```

跑測試：

```bash
node test/pure.test.mjs     # 純邏輯，幾秒
node test/calibrate.mjs 60  # 量門檻，約一分鐘
node test/e2e.mjs           # 真瀏覽器，需要 google-chrome
```

**負控制不能省**：沒蓋浮水印的圖必須驗不出來，別人的金鑰也必須驗不出來。做偵測類功能只量「抓得到」是不夠的，不然做出來的不是偵測器，是一個永遠說是的按鈕。
